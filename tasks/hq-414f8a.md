The user clarified that the default active-time limit is 16 hours, intended to prevent runaway sessions lasting roughly 48 hours and consuming about 250 million tokens. The CLI correctly stores active_seconds=57600, but renders active 0:16/16:00 without units. An agent misread that as a 16-minute cutoff despite paused:no, interrupted a healthy baseline, and requested an unnecessary budget override. This was an agent interpretation error, not evidence of an enforcement bug. Render hours/minutes explicitly in both status and limits, or label the format, so agents do not compare elapsed minutes to a limit in hours; preserve the existing 16-hour default and enforcement.
