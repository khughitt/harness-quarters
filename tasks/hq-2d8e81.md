Why: Repeated session openings suggest a small launcher could reduce copying task ids, artifact paths and review context into a fresh session. The owner supplied a completed seven-day first-prompt inspection on 2026-10-24 and wants no further session collection. Read [ref:brief] for the findings, limits and proposed first action.

Desired outcome: Start with review <task-id>: resolve the intended artifact and its reviewed revision from task metadata, show the generated prompt for editing, and only later launch the selected harness/home. The supplied experiment reports 44 review cases with a resolved task record, 25 with spec/plan fields, 13 with SHA-bearing notes and 3 with a worktree in a review note. These are preliminary coverage observations, not proof that every review target is reconstructible.

First milestone: A local, dry-run-only prompt builder evaluated against the existing cases, reporting supported, missing and ambiguous fields. It must preserve distinctions between spec, plan, code, fixes, brief, ledger, PR and pasted-report review. Do not guess a target from the latest note or assume a SHA identifies the requested artifact.

Later possibilities retained from the source: take/review/execute/scope/next actions; target selection with fzf over recent tasks and linked artifacts; harness/home selection and possibly sending the same prompt to two harnesses; crew flows as another consumer; ops shared CLI vocabulary, project colours and compatible identifiers; lore-owned prompt text once multiple consumers need it; links between prompt text and flows; optional text search, tf-idf/BM25 or embeddings if a demonstrated retrieval problem needs them. None is in the first milestone. Repeated cross-harness prompts motivate preserving harness choice but do not yet settle a --harness both feature.

Where to look: tools/hq_cli/{cli,sessions,launch}.py, tools/hq.toml, the existing session-search work hq-3558a1 / hq-ea0975, and [ref:brief]. Session search resumes old conversations and remains a separate question. Production CLI spelling and any structured handoff changes are decisions after the dry run; ops vocabulary adoption belongs with an actual hq CLI change.
