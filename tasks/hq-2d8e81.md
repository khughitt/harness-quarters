Why: Repeated session openings suggest a small launcher could reduce copying task ids, artifact paths and review context into a fresh session. The owner supplied a completed seven-day first-prompt inspection on 2026-10-24 and wants no further session collection. Read [ref:brief] for the findings, limits and proposed first action.

Original desired outcome (retained, not the selected first interface): Start with review <task-id>: resolve the intended artifact and its reviewed revision from task metadata, show the generated prompt for editing, and only later launch the selected harness/home. The supplied experiment reports 44 review cases with a resolved task record, 25 with spec/plan fields, 13 with SHA-bearing notes and 3 with a worktree in a review note. These are preliminary coverage observations, not proof that every review target is reconstructible.

Established by hq-268cc2 (report committed in 7d66d22): Only three of the reported 44 mappings were recoverable: one historical implementation target matched, two were misbound, and 41 identities remain unavailable. These differing examples are not representative coverage. The old helper required separate investigator checks of repository/artifact availability; closed records establish no active review. Read [ref:dry-run] before repeating any experiment.

Completed milestone (hq-2b3929; original bound retained): One local, dry-run-only editable-draft experiment with a frozen per-case manifest, using the retained C01/C02/C03 examples plus explicitly labelled controlled variants for missing, conflicting and stale handoffs. Explicitly select review kind, repository, target artifact or code scope and matching frozen revision; validate repository identity, commit/blob availability or out-of-tree artifact hash inside the helper. Keep historical reconstruction distinct from current review readiness. Preserve distinctions between spec, plan, code, fixes, brief, ledger, PR and pasted-report review; unsupported kinds remain explicit rather than falling back to a spec or plan. Show editable previews locally and report required manual corrections and supported, missing, conflicting, stale or unavailable fields. Do not guess a target from the latest note or assume any SHA identifies the requested artifact. No new session collection or reconstruction of the missing 41 identities.

Later possibilities retained from the source and follow-up notes: offer the preceding choose-next recommendation as a suggested target (never authority for a review revision); take/review/execute/scope/next actions; target selection with fzf over recent tasks and linked artifacts; harness/home selection and possibly sending the same prompt to two harnesses; crew flows as another consumer; ops shared CLI vocabulary, project colours and compatible identifiers; lore-owned prompt text once multiple consumers need it; links between prompt text and flows; optional text search, tf-idf/BM25 or embeddings if a demonstrated retrieval problem needs them. None is in the first milestone. Repeated cross-harness prompts motivate preserving harness choice but do not yet settle a --harness both feature.

Where to look: tools/hq_cli/{cli,sessions,launch}.py, tools/hq.toml, the existing session-search work hq-3558a1 / hq-ea0975, and [ref:brief]. Session search resumes old conversations and remains a separate question. Production CLI spelling and any structured handoff changes are decisions after the dry run; ops vocabulary adoption belongs with an actual hq CLI change.

Established by hq-2b3929 (merged at 0ed7d6b): Explicit selection produced validated historical drafts for 3/3 observed cases; 3/3 derived missing/conflicting/stale variants blocked as expected. Task identity needed correction in 2/3, revision in 1/3 and kind in 1/3. The implementation draft omitted final verification counts from a pasted report, and the verdict check missed an acceptance before the merge commit. The artifact-path proposal was checked post-hoc: revision independently confirmed for 1/2 spec cases, task matched in 2/2 partly by construction. These results establish no population coverage or current handoff. Read [ref:drafts] for the detailed limits.

Next milestone: hq-7be4e4 designs a narrow print-only preview starting from the artifact path a request already gives; an implementation review, if included, still needs an explicit commit. Settle candidate versus authoritative revision, named checkout/worktree, repository/blob validation, differing working bytes, ambiguous task matches, prior verdicts and later revisions. Existing refs/notes come first; no shared-schema prerequisite is established. The preview prints text for a person to edit; it launches nothing. Design and plan reviews remain gates before any later implementation.

Next action: Wait on hq-7be4e4's reviewed design and recommendation, then re-scope this idea. Keep the production launcher unscoped. hq-2d8e81 continues owning all three retained private evidence bundles until that design result or a stop decision permits a reviewed preservation/disposition choice; no deletion or recollection.
