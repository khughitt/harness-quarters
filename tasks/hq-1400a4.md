Why: A paused agent must be able to park and note its claims from the authoritative checkout. Main can refuse stale records, while the closing allowlist rejects the directory selector needed to reach the worktree. The originating transcript confirms both failures and the Stop hook's live-claim refusal.

Established at hq 514658992ab9b9c1068994a8b6129e4adf9e5d08: tools/turn_pause/allowlist.py shell() delegates tasks commands to _records(), which treats argv[1] as the subcommand. Therefore tasks -C <directory> park/note is refused as "tasks -C". The installed tasks CLI documents -C <DIR> as its directory selector. The existing design [ref:pause-contract] requires park and note to remain bookkeeping during and after grace; it already accepts their repository hooks.

Done:
- Accept the explicit simple-command form tasks -C <directory> park/note ... by parsing the directory selector before checking the existing subcommand allowlist. Keep plain tasks commands working. No cd, env wrapper, compound command, or general shell exception is needed.
- Preserve the existing classifications for record reads/attachments and their grace limit, the show --no-fetch requirement, protected-path checks, shell scan, command length bound and refusal of unlisted subcommands. A directory selector must never make tasks start/done or malformed commands pass.
- Add focused parser regressions for relative, absolute and quoted paths, missing/empty selector values and unsupported commands; cover the hooked paused path for park and note during and after grace, for both harnesses.
- Confirm an isolated temporary project can receive a note and release an owned claim through the allowed -C form from another cwd, without touching real task stores or host git configuration. Use an explicit subprocess environment under the repository's test rules.
- Update current user guidance with the worktree closing form. Record focused RED-to-GREEN and the policy-appropriate repository checks; the documented full-suite route is just test. Any live hook activation remains a separate user-authorized host action.

Original report (preserved):
After the turn-pause limit tripped, the pause hook told the agent to park its task, and claim-guard's Stop hook refused to let the turn end while two claims were live. The task records lived in a git worktree whose copy was newer than the main checkout's, so tasks park from the main checkout failed with stale_copy. Every route to run tasks in the worktree was refused while paused: cd, env -C, and tasks -C. Expected: the closing allowlist lets a paused agent run tasks park and tasks note against the checkout that holds the claim, for example by allowing tasks -C or a cd into a registered worktree. What happened: the agent could neither park nor note, and the user had to run the park by hand. The pause message also names the park as required, so the two hooks contradicted each other with no route that satisfies both.
