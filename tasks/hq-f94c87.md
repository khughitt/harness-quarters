Why: `harnesses/agy/hooks.json` invokes `~/d/hq/harnesses/agy/hook` by checkout path for `SessionStart`, `PreToolUse`, and `Stop` (whereas `Stop`'s second hook uses `~/.local/bin/harness-state-refresh`), so relocating the script in-tree breaks `PreToolUse` with exit status 127 in open Antigravity CLI sessions until restart and leaves a checkout-internal path in host hook config (see [ref:drift-brief] and hq-fe88ef).

Done:
- `links.toml` `[required]` declares `"~/.local/bin/agy-hook" = "harnesses/agy/hook"` and `harnesses/agy/hooks.json` (`SessionStart`, `PreToolUse`, `Stop`) invokes `~/.local/bin/agy-hook`.
- `tools/test_agy_hooks.py` verifies that invoking `harnesses/agy/hook` through an external symlink still resolves `ROOT` (`Path(__file__).resolve().parents[2]`) to the checkout, and wiring assertions in `tools/test_agy_hooks.py`, `tools/test_claim_guard_wiring.py`, and `tools/test_capture_notice_wiring.py` pass under `just test-one tools/test_agy_hooks.py tools/test_claim_guard_wiring.py tools/test_capture_notice_wiring.py` and `just check-hygiene`.
- `docs/runbooks/adding-a-harness.md` notes that Antigravity CLI caches hook command strings in memory at session startup and that hook entries should point at declared `~/.local/bin/` links.

Where: `links.toml`, `harnesses/agy/hooks.json`, `tools/test_agy_hooks.py`, `tools/test_claim_guard_wiring.py`, `tools/test_capture_notice_wiring.py`, `docs/runbooks/adding-a-harness.md`.

Original feedback:
When a hook configuration entry points directly at a checkout-internal script rather than a stable link target, or when a layout migration moves the script while a session is open, running sessions continue invoking the startup-cached command string and fail PreToolUse with exit status 127 until the harness process restarts.
