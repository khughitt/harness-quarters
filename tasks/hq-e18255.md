Why: capability evidence can trail the installed harness without any warning. On 2026-10-10 this host reports Claude Code 2.1.296 versus facts probed on 2.1.295, and Codex 0.162.1 versus facts probed on 0.156.1. The completed hq-b2515c probe established no value change and left the Codex aggregate inconclusive; version drift must therefore be visible without being mistaken for a changed capability.

Approach: add an explicit tools/harness-facts stale command using the existing validator and view. Compare each probed entry's version with the installed harness version, once per relevant harness per invocation. Treat any version mismatch, including patch versions and downgrades, as evidence for a different version; do not infer ordering or changed behavior. Normalize only the known CLI version wrapper. Report fact, harness, probed version, and observed installed version. Unknown entries remain unknown and never become stale probed values. Missing binaries, timeouts, nonzero exits, or unrecognized version output must be reported as an unavailable comparison, never as up-to-date.

Run the reporting command from just test as an advisory check: mismatches or unavailable comparisons are visible warnings, while invalid fact data remains an error. Keep get, list, lookup, and schema validation independent of installed binaries. No upgrade hooks, automatic task filing, fact refresh, new consumer policy, or live probe is part of this change.

Done: deterministic tests with fake version commands cover a match, patch mismatch, downgrade, differing per-fact probe versions, unknown entries, missing binary, timeout/failure/malformed output, and invalid facts. Assert no fact file mutation and no version subprocess on existing read paths. just test passes; README documents the command, advisory behavior, unavailable comparisons, and re-probe action.

Where to look: tools/harness-facts (validate/view/main), tools/test_harness_facts.py, justfile, README.md capability facts and re-probing sections, docs/notes/2026-10-08-declared-surface-drift-brief.md. Keep existing parent hq-72fd4b. Direct process is appropriate because reporting policy, integration point, and verification are settled; remaining version parsing and output choices are bounded.
