Question: Which supported cli-pane interaction lets the user search thoughts as they type, shows title, alias and readable tags with a useful color cue, and opens the pick in the pane outside the conversation; and where does that color come from without copying mindful's palette?

Established by the 2026-10-13 re-scope (Claude Code 2.1.296 generated types, mindful 0.1.0; do not re-derive):
- Select options are `{value, label?: string}`: no styled labels. Select has no highlight callback, only `onSelect` on a pick, so a preview of the highlighted row is not possible with Select.
- Button takes children of strings and `Text` (a chip, a dim part) as one pressable row, and is on every surface, mobile included. A column of Buttons under an Input is the candidate for styled, tag-bearing result rows.
- Input has `onInput` on every change and `onSubmit` on Enter. Mobile has neither Input nor Select.
- `mindful --color=always search` prints no color, and its rows show score, alias and title only. `mindful --json search` rows carry title, alias, tag aliases, and `visualIdentity` and `style` slot indices, not resolved colors. Colored output exists only in `mindful --color=always show`, the identity art, which the pane's SGR path already renders for `/m <id>`.

Where to start: claude/mods/cli-pane/hooks/register.tsx and sgr.ts; claude/mods/cli-pane/tests/cli-pane.test.ts, which already runs under `claude plugin test` (`just mods`) with `process.run` and `ui.open` answered by test hooks. `$.ui.mount` there drives an Input, Select or Button headlessly per surface; it checks the tree a hook returns, never a surface's paint. Types: claude/mods/cli-pane/.claude-plugin/types/claude-code/index.d.ts (generated, untracked; InputProps, SelectProps, ButtonProps). Use the plugin-authoring skill. Read mind6-96e1c0's decision to adopt the /tas pane approach. Handoff: docs/notes/2026-10-10-context-discovery-brief.md.

Bound: At most 45 minutes, inside the existing test harness with two synthetic thoughts (tags, known SGR). Mount Input plus a Button list on terminal and mobile, and test typing, focus, picking, the empty and error results, and two overlapping searches answered out of order: the later query's rows must win. For the color cue, decide between (a) no color in rows, with the picked thought's `show` art in the pane as today, and (b) a resolved color per row that mindful would have to emit (a mind6 change). No production implementation, live desktop interaction, new completion engine, whole-corpus scan, or palette logic in hq.

Expected result: Record the supported interaction, the color source, and the implementation boundary with its tests on this task and in the brief. If (b), file the mind6 request it needs and name it.
