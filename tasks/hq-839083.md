Why: finding a past agent session today means remembering which harness, home and directory it ran in, then using that harness's own `/resume` picker. One command should list recent sessions across Claude Code and Codex, personal and work homes, and launch the one picked in its own harness, home and cwd.

Approach (settled by hq-434be2, `docs/notes/2026-10-15-session-discovery-contract.md`; launch flags decided by the user 2026-10-15):

- Command: `tools/hq` with a `sessions` subcommand, linked to `~/.local/bin/hq` through `links.toml`. `hq sessions` lists; `hq sessions -i` picks interactively (fzf when on PATH, otherwise a numbered prompt) and launches. Chosen over the source thought's `hq list sessions` so later verbs (`hq sessions search`) group under the noun; the thought's `--codex` becomes `--harness codex`.
- Sources, read-only, no index of its own: Claude `<home>/history.jsonl` (`sessionId`, `project`, `display`) with transcript at `<home>/projects/*/<id>.jsonl` (directory-entry match, not a computed slug); Codex `<home>/state_5.sqlite` `threads`. Homes: `~/.claude`, `~/.claude-work`, `~/.codex`, `~/.codex-work` (as `tools/session_archive/config.py:sources`).
- Rows: harness, home, short id, recency, cwd (`~`-shortened), label (Codex `name`/`title`; Claude first history `display`, trimmed), `cwd missing` mark. Newest first, 20 by default. Recency: Codex `recency_at_ms`; Claude transcript mtime, falling back to last history `timestamp` only when the stat fails.
- Visibility: every home and project by default. Filters `--harness claude|codex`, `--home personal|work`, `--here` (cwd inside the current checkout or one of its worktrees), `--archived` (Codex archived threads, hidden by default). Codex rows with empty `preview` stay hidden.
- Excluded and counted in one footer line: subagents (Codex `source` not `cli`/`vscode` or `thread_source` not `user`/null), `exec`/SDK runs, Claude sessions with no transcript, history lines without `sessionId`, malformed lines. Never use Codex `has_user_event` (0 on every row).
- Fail early: a missing `state_5.sqlite`, or a `threads` table lacking a read column, is an error naming the file (internal schema; a version bump must stop the list, not empty it).
- Launch: `exec` in the recorded cwd. Claude `claude <flags> --resume <id>`; Codex `codex <flags> resume <id>` (flags before `resume`). Work rows set `CLAUDE_CONFIG_DIR=~/.claude-work` / `CODEX_HOME=~/.codex-work`; personal rows unset both (setting `CLAUDE_CONFIG_DIR=~/.claude` would read a different `.claude.json`). Refuse, naming the path, when the cwd or transcript is gone; never launch elsewhere.
- Per-home flags live in one tracked TOML config beside the tool, keyed by home. Values today: `claude`, `claude-work`: `--dangerously-skip-permissions` (aliases `cl`, `clw`); `codex`, `codex-work`: `--no-daemon --dangerously-bypass-approvals-and-sandbox` (aliases `cor`, `cowor`; the work values follow the work resume alias, not the plain work launcher). A home missing from the config is an error, not an empty flag list.

Done when: `hq sessions` and `hq sessions -i` behave as above; tests (in `just test`) run against synthetic homes under a temp dir and stub `claude`/`codex` executables that print argv, cwd and both home variables, covering each source, every filter, each exclusion and its footer count, the schema-drift error, both refusals, and the personal/work environment for both harnesses; `links.toml` carries the `~/.local/bin/hq` link (applied from main after merge); README.md documents the command.

Out of scope: full-text search and a sessions TUI (filed as their own idea under hq-65f661); the 491 pre-2026-07-08 personal Codex rollouts without a `threads` row (left out of the list and named in the footer or README); filtering agent-driven interactive probes; mobile.

Where to look: `docs/notes/2026-10-15-session-discovery-contract.md` (sources table, sample rows, stub-launch results); `docs/notes/2026-10-10-context-discovery-brief.md`; `tools/session_archive/config.py` (home list); `agents/bin/session-episodes` (header readers); `tools/harness-facts` and `tools/session-archive` for tool layout and test style.
