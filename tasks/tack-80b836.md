Question: Can a harness Stop hook refuse to end a turn while the session holds a live tasks claim that is neither parked nor done — an abandoned claim — and can it see the actual owner's obligation (not just any claim)? What does tasks need to expose for it to know?
Premise, corrected 2026-09-21 review: this gate covers the abandoned-claim stall (ai-c62995's second instance: a subagent with all work in hand ended its turn to wait on a background monitor and never resumed). It does not cover ai-c62995's first instance — an agent repeatedly parking a claimed, unblocked task between red-green increments — because a park releases the claim and the hook would let that through. Inappropriate parking stays open on ai-c62995 as a guidance problem, not a hook problem.
Where to start: ops hooks/claude-pretooluse and hooks/claude-sessionstart for the hook idiom and how the session is identified; the tasks claim store (tasks skill: start records a claim with the session identity and a liveness handle; prime and ready read it); Claude Code hooks reference for Stop (decision: block, stop_hook_active); Codex hooks.json stop entries (mindful/v6/.codex/hooks.json carries one) and whether a stop hook can block or only inject; relay's dispatch (ops docs/specs/2026-09-16-relay-design.md) for where such a hook should eventually live.
Bound: a probe in a throwaway CLAUDE_CONFIG_DIR and CODEX_HOME with a stub hook; no production wiring, no tasks changes. Cover, not just one synthetic stop: (1) this session's unparked claim — refused; (2) another session's live claim — not refused; (3) a legitimate park (tasks park before the turn ends) — not refused; (4) the guarded retry (stop_hook_active or the Codex equivalent) — not refused a second time; (5) the stalled-subagent shape — a subagent that started a task and ends its turn: does the hook fire in the subagent's stop, the controller's, or neither, and which session does the claim name.
Expected result: per harness and per case, whether the stop was refused and what input named the session; the exact tasks query the hook needs (existing command or a gap to file in tasks); whether the hook can see the owner's obligation for the subagent case. Recommendation on this task and in docs/notes/2026-09-21-flow-gates-brief.md §5. Measuring the effect: obs's stall proxy counts a park as handled (obs/docs/reports/first-baseline.md), so a hook that induces parking can lower the incident rate without reducing unnecessary stops — the judgment after rollout must separate resumed progress, legitimate parks, and unnecessary parks, which the proxy alone does not.
Ideas it wakes: on completion, tasks note ai-21ea5d, ai-c62995, and ai-21aaa3 with the finding, in the same commit as this result.
