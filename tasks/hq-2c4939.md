Why: an inline execution in prism treated approval of a visual-validation plan as permission to launch test windows and switch workspaces, repeatedly, on a desktop the user was using. The global Processes section already asks for the machine before extended runs that need the user off it, and tasks has `park --reason quiet` for work that needs an idle host; neither says that taking the live desktop is that kind of action.

Done when the global Processes section says: work that takes the live desktop (opens windows on it, moves focus, switches workspaces, captures the screen) is a host-use action. Approving a plan does not grant it. Prefer a nested or headless compositor where the project has one; otherwise ask at that moment, naming what will appear and for how long, or `tasks park --reason quiet` it. A retry or a later capture asks again rather than reusing an earlier yes. Check the edit renders in every AGENTS.md mirror.

Where to look: AGENTS.md "Processes", the extended-run bullet ("above all one that needs the user off the machine"); the tasks skill's `quiet` park reason; niri-material's AGENTS.md idle-host capture bullet as an existing project-level example.
