Why: hq-fa8757 found that mindful v6 already holds agent-authored briefs and plans verbatim with stable ids (--as agent:<id>@<model>, --by filter, aliased tags, sets), but tasks cannot link a --plan/--spec/--step outside the repository (validate_doc_shape rejects anything but a repo-relative .md under plan_dirs/spec_dirs, and step_exists reads the file directly), and obs treats a non-path plan string as a repository path, so plan-round authorship silently degrades. Changes land in two projects at least, which the brief (lore:docs/notes/2026-10-02-agent-working-docs-brief.md §6) names as the trigger for a design task.

Decide: the reference form (mindful:thought:<hex> as today's sources use, or thought:<hex> as mindful show accepts); the tasks extension (an external-link form accepted before path validation, a configured fetch per scheme so the tracker stays ignorant of mindful, one Resolver::read used by step_exists, check's heading reads and the doc_missing check, a doc_unreachable finding); the obs changes (scheme-prefixed plan/spec -> no_path instead of a bare unknown; DOC_PATH/KIND_CUES recognise the reference; optionally mindful writes as a plan-round authorship signal); the collection shape in mindful (shared corpus, agent owner, aliased #agent-docs tag, per-kind tags, optional per-project set; no separate home) and the write path when the web app holds the writer lock (POST /api/op with actor); the profile value (design_docs: mindful) and which doc kinds it covers; and how an agent writes a long plan edit, since mindful edit has no --body-file.

Bound: design and user review only; file the implementation as children per project (tasks, obs, mind6 if any, ops for the profile value). Evidence: hq-fa8757's notes.
