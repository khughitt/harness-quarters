Why: an agent looking for a file a skill's relative link names ran a recursive file search over the shared skills directory, got no results, and reported the file missing although it sits inside the linked skill directory. The declared links install each skill as a directory symlink (and README.md as a file symlink), and rg, fd and find without -L skip symlinks by default, so any search rooted at the skills directory is silently empty. Reporter's expected outcome: either a layout or capability fact that says searches there need -L/--follow, or a layout a default search traverses.

Established at scope (2026-10-23, links.toml at 7382893):
- Reproduced: under ~/.agents/skills, `rg --files`, `fd -t f` and `find -type f` each list 0 files; with -L they list 97-98. A search rooted at one skill link (`rg --files ~/.agents/skills/scope`) works.
- Same shape in every link-assembled directory: ~/.agents (evals, flow, profiles, vendor), ~/.agents/bin, and the harness homes' skills/ directories (links.toml [harness.*.links]).
- A traversable layout is rejected: the entries target different owner checkouts (lore, tasks, flows, ops, hq), so no single directory link can replace them, and copies would drift from their owners. A host-wide rg --follow (ripgreprc) is rejected too: it would also descend into every checkout's `.worktrees` symlink.
- A capability fact does not fit: harness facts record harness behaviour, and this is rg/fd/find behaviour. Whether harness-native search tools (Claude Code Grep/Glob, pi find/grep) follow these links is a separate, unprobed question; file it only if an agent hits it through a native tool.

Done:
1. README.md Layout (the links.toml bullet) states that link-assembled directories hold one symlink per entry, so a search rooted there needs -L (`rg -L`, `fd -L`, `find -L`), or should run in the owner checkout the entry resolves to (`readlink -f`, or the links.toml target).
2. A one-line comment above the aggregate-surface block in links.toml says the same.
3. Agents read neither file at search time, so file one `tasks feedback --project lore ... --category gap` proposing a Shell bullet in the global instructions: an empty search under ~/.agents or a harness skills directory is not evidence of absence; rerun it with -L or resolve the link first. Record the returned id on this task.

Check: `just test` passes; the README sentence names the -L forms that the reproduction above confirmed work.

Where: README.md "## Layout"; links.toml lines 26-28; lore instructions/AGENTS.md "## Shell" (lore's to change).
