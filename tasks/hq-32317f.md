Why: agy sessions start test and build runners at full CPU width, while Claude Code, Codex and pi default PYTEST_XDIST_AUTO_NUM_WORKERS, CARGO_BUILD_JOBS, RUST_TEST_THREADS, NEXTEST_TEST_THREADS and GOMAXPROCS to 4 (hq-cffc71, a2ebc48c; held equal by tools/test_worker_defaults.py). Part of ops-4adbbe.

Established (hq-a29f17, agy 1.5.3, BuildID 50b5b6c0ca95a2a401f0c806222ecaa6; [ref:brief] Section 7 has the evidence, so do not re-derive it): agy has no native settings or hook environment surface; run_command shells inherit agy's process environment unchanged; the updater and agentapi shim resolve the binary through os.Executable(), so a bash wrapper that execs the real binary stays update-safe. The supported route is an hq launcher, mirroring harnesses/pi/bin/pi.

Done:
- harnesses/agy/bin/agy: bash launcher that fails closed (exit 127 with a diagnostic) when ${AGY_BIN:-$HOME/.local/share/agy/agy} is not executable, exports each of the five defaults as ${!var:-4}, leaves LIBRARY_VARS and GRANT_VARS alone, and execs the binary. The script is in [ref:brief] Section 7 item 4.
- links.toml [required] declares "~/.local/bin/agy" = "harnesses/agy/bin/agy" beside the pi entry.
- tools/test_worker_defaults.py gains an agy_installed fixture and agy_env helper and the four focused tests named in [ref:brief] Section 7 item 5 (sets the defaults, keeps a given value, yields to a host-budget grant, fails closed when the binary is missing), passing under just test-one; just check-hygiene passes.
- Activation, after merge and with the user's approval at that moment (a host change): move the ELF from ~/.local/bin/agy to ~/.local/share/agy/agy, run just link --apply from main, then confirm a fresh agy session's run_command shell shows the five values as 4.

Watch for: GOMAXPROCS=4 also caps the agy Go process itself (inferred, acceptable unless agy slows); an agy reinstall script that writes ~/.local/bin/agy could follow the symlink and overwrite the tracked launcher, so check how the installer writes before activation and note the result here.

Where: harnesses/pi/bin/pi and its tests as the model; links.toml; tools/harness-links (refuses to replace a regular file, hence the move); [ref:brief].

Original body (2026-11-02): hq-cffc71 set PYTEST_XDIST_AUTO_NUM_WORKERS, CARGO_BUILD_JOBS, RUST_TEST_THREADS, NEXTEST_TEST_THREADS and GOMAXPROCS to 4 for Claude Code (settings env), Codex (shell_environment_policy.set) and pi (pi/bin/pi), held equal by tools/test_worker_defaults.py. agy 1.4.12 showed no settings key for its tool shell's environment, and ~/.local/bin/agy is its own binary rather than an hq launcher, so agy sessions still start unbudgeted runners at full width. Options: an hq launcher in front of agy (links.toml), or an env setting if a later agy version offers one. Part of ops-4adbbe.
