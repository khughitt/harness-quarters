Why: hq's session tools (hq sessions, tools/session-archive, agents/bin/session-episodes, the session-logs skill) know only Claude Code and Codex, each through code written for that harness and spread across sessions.py, launch.py, color.py, cli.py, session_archive/{config,inputs,decide,prune}.py and session-episodes (docs/runbooks/adding-a-harness.md section 7 lists the edit points). The user wants parity for every harness in use (agy, pi, Crush, opencode), and harness-specific logic gathered in one place per harness rather than spread across these tools.

Done:
- Each harness's session store is read through one adapter per harness behind a shared seam (designed and first used by hq-57d68e for agy); adding a harness touches that adapter and its registration, not every tool.
- agy, pi, Crush and opencode reach parity with Claude Code and Codex in hq sessions (list and resume), session-archive (capture; prune stays off until obs indexes the store), session-episodes and the session-logs skill.
- Where a harness cannot meet parity, the gap is recorded as a capability fact in facts/capabilities.toml with its evidence, not left implicit.
- docs/runbooks/adding-a-harness.md section 7 describes the adapter route.
