Piece of the science-harness-on-pi goal (ops, filed 2026-10-11 with this task). pi (earendil-works/pi) reached 1.0.0 on 2026-10-01 and is at 1.1.0 (2026-10-07): it now has MCP over stdio and streamable HTTP (packages/mcp, docs/mcp.md), an experimental durable runtime (packages/durable, exporting Harness: durable submissions idempotent by request id, task-owned child conversations, bottom-up abort, per-conversation usage and cost), codemode, and RPC mode. The local clone under ~/software/pi is at 0.85.1 and describes none of this; nothing is read from it.

Outcome: pi installed at a pinned version in a declared harness home, and capability facts in facts/capabilities.toml for that version, each with probe evidence and unknown kept distinct from unsupported. Name the runtime path on every fact: the CLI and RPC path, and the pi-durable path, are different runtimes with different guarantees, and a feature documented for pi-durable is never recorded as a fact about the CLI path. Facts the downstream probes need: MCP stdio connection to a local server; RPC commands available headless (prompt, steer, abort, fork, stable session id); how each path exposes durable submissions, child conversations and cancellation; whether an interrupted turn resumes and what it replays; what usage and cost each path reports and whether children are included.

A pi or model upgrade is a new epoch: the facts are per version, and an upgrade reruns the probes before any unattended use.

Done: the home declared, the facts committed with evidence, and a note on the ops goal naming the pinned version and the runtime path recommended for the attended probe.
