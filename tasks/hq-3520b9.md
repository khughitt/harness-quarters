Why: the plain listing is hard to scan at 20+ rows. Colour should separate classes at a glance and show age as a gradient (user suggestion, 2026-10-15).

Approach:
- Flag: `--color auto|always|never` (default auto: colour only when stdout is a TTY, off when NO_COLOR is set), matching the tasks CLI's `--color` and NO_COLOR handling rather than a new `--pretty`/`--colors` spelling. `-i` passes `--ansi` to fzf so the picker shows the same colours. The numbered prompt colours as the listing does.
- Classes: harness (one hue each for claude and codex), home (work rows set apart, e.g. a marker or tint), `cwd missing` dimmed or warned, archived Codex rows dimmed under `--archived`. Option worth trying: paint the cwd with the tasks project's identity colour (`color` in tasks/.config.toml, the colour `tasks --color=always projects` uses) when the cwd is inside a registered project. Read it through the tasks CLI, not by parsing the registry.
- Age: a continuous sequential colormap over log-scaled age (minutes to months span four orders of magnitude, so a linear scale would put nearly every row at one end), in 24-bit colour with a 256-colour fallback. Use a perceptually uniform ramp that stays legible on dark and light backgrounds. The dataviz skill's palette method applies.
- Colour must not change column widths: pad before painting.

Done when: tests cover auto/always/never, NO_COLOR, non-TTY output staying plain, and that stripping ANSI codes from the coloured output gives the plain output exactly; the colormap is monotone in age; README documents the flag; the user has looked at a screenshot of a real `hq sessions --color=always` listing on a dark terminal and accepted the colours (a judgement gate, not a check the agent can pass).
