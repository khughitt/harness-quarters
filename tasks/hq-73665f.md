Deferred minors from hq-fc34cb's fresh review (tools/hq_cli/cli.py reader_shut):
1. A listening AF_UNIX stream socket on stdout or stderr makes the zero-length send raise OSError ENOTCONN, which escapes broken(); inside silence_broken() in main's handlers it buries the original error under a chained traceback. Suggested fix: decide whether reader_shut returns False on OSError other than EPIPE (the probe is inconclusive, so the later real write error surfaces) or keeps failing loud; add a test with a listening socket as stdout.
2. socket.socket(fileno=os.dup(fd)) sets O_NONBLOCK on the shared file description if socket.setdefaulttimeout() was ever called in the process. hq never calls it, so this is latent. Suggested fix: a comment at reader_shut naming the dependency, or a guard asserting socket.getdefaulttimeout() is None.
Done when each is fixed or recorded as accepted with its reason.
