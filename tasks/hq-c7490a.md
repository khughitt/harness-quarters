Why: hq-e83a8c made prune keep every Codex thread that has more than one rollout file, and every lone continuation segment, as kept:segmented-thread. That fails closed because prune deletes per thread with codex delete --force <thread>, and what that command does to continuation segments (rollout-<ts>-<thread>_<segment>.jsonl, Codex 0.165+) is unverified. The delete protocol (lock, quarantine link, delete, freeze check, re-verify) also handles one rollout path per unit. As more threads segment, more sessions will stay unpruned.

Done: probe in a disposable Codex home (the probe.py pattern) whether codex delete --force <thread> removes the base and every segment, and whether it touches archived_sessions; record the result as a capability fact. Then either extend the delete protocol to quarantine-link and verify every segment of a thread as one unit (all segments inactive and archived first), or keep the refusal with the probe evidence recorded. Also covers: a base in sessions/ whose segments sit in archived_sessions is not counted as segmented today; the fake codex in testing.py and probe.py globs see base files only.
